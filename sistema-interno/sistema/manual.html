Cómo usar este manual

Navegá por los módulos desde el menú lateral izquierdo. Cada sección explica el flujo completo de trabajo, las funciones disponibles y los casos de uso más frecuentes.


Si sos nueva en el sistema, empezá por Acceso y Sesión → Panel Principal y después avanzá al módulo que corresponda a tu rol.

Principios del sistema

Todo queda registrado

Cada movimiento de caja, cada evolución clínica, cada cambio de configuración queda sellado con nombre de usuario y timestamp. La auditoría es permanente e inalterable.

Los módulos se hablan

Cuando confirmás un suero en Caja, el stock se descuenta en Laboratorio. Cuando convertís un lead en CRM, el expediente se crea en Pacientes. Todo está conectado.

Primero los datos, después las acciones

El sistema necesita que cargues el plan de cuentas, los tipos de tratamiento y las personas antes de operar. Admin es el cerebro que alimenta al resto.

Cada quien ve lo que le corresponde

El acceso a cada módulo se controla por permisos individuales que define la administradora desde Admin → Usuarios. Las acciones sensibles (borrar o restaurar datos) se realizan de forma controlada desde Firebase Console, no desde el sistema, para evitar accidentes.

Módulo de Acceso
Login y sesión
Cómo entrar al sistema, gestionar la sesión y recuperar la contraseña.

Iniciar sesión

1

Ingresar email y contraseña

Usá el email con el que te registraron en el sistema. La contraseña es la que seteaste vos. El sistema distingue mayúsculas y minúsculas.

2

Clic en "Entrar al Sistema"

El sistema verifica tus credenciales contra Firebase Authentication y luego carga tus permisos desde Firestore. Si todo está bien, entrás al Panel Principal.

3

Los módulos visibles dependen de tus permisos

Si no ves un módulo en el Index o en el sidebar, es porque no tenés el permiso habilitado. Contactá a la administración.

Olvidé mi contraseña

Hacé clic en "¿Olvidaste tu contraseña?" en la pantalla de login e ingresá tu email. Por seguridad, el sistema siempre muestra el mismo mensaje (no revela si el email existe o no). Si la cuenta existe, te llega un link de recuperación a tu casilla.


⚠ Si el mail no llega, revisá spam. Como alternativa, una administradora puede resetear tu contraseña desde Firebase Console (ver sección Administración → crear/gestionar usuarios).

Bloqueo por intentos fallidos

Después de 5 intentos incorrectos, el sistema bloquea el acceso por 15 minutos. Si necesitás entrar antes, abrí el login en una ventana de incógnito o esperá los 15 minutos.

Cierre de sesión automático

Por seguridad, el sistema cierra la sesión automáticamente después de un tiempo de inactividad. Ese tiempo lo configura la administradora desde Admin → Alertas y Sesión (15, 30 o 60 minutos, o sin límite). Cualquier clic, escritura o movimiento del mouse reinicia el contador.


Unos minutos antes de cerrarse, aparece un aviso ("Tu sesión expira en X min") para que puedas seguir trabajando si movés el mouse. Al expirar, te lleva al login y cierra la sesión real de forma segura.


Para cerrar sesión manualmente, usá el botón SALIR en el Panel Principal.

Panel Principal
El dashboard
El centro de comando. Todo lo importante de un vistazo.

KPIs en tiempo real

Ingresos Hoy

Total de cobros del día en todas las cuentas. Se actualiza en tiempo real con cada movimiento de Caja.

Turnos Hoy

Cantidad de turnos programados para el día de hoy en Agenda.

Pacientes Activos

Total de expedientes en la base de datos.

Sin Visita

Pacientes que no consultaron en los últimos 30 días (configurable en Admin).

Saldos disponibles

Muestra el saldo actual de cada cuenta configurada (Efectivo, Bancos, Billeteras, etc.). Los datos vienen de Caja en tiempo real. Si el saldo de una cuenta no cuadra, revisá los últimos movimientos en Caja.

Alertas del sistema

La zona de alertas muestra banderas rojas y naranjas cuando hay situaciones que requieren atención:


  • Rojo — Insumos bajo stock mínimo: muestra los nombres y cantidades de los insumos críticos. Clic para ir a Laboratorio.
  • Naranja — Vencimientos próximos: insumos que vencen en los próximos 30 días.
  • Fluo — Cumpleaños del día: pacientes que cumplen años hoy con botón de WhatsApp directo.

Pacientes inactivos

Lista de pacientes que no tuvieron consulta en el período configurado. Cada uno tiene un botón WSP que abre WhatsApp con un mensaje de reactivación pre-cargado. El mensaje se puede enviar en un clic.


Para cambiar el período de inactividad: Admin → Config del Sistema → Alertas del Sistema.

Buscador global

La barra de búsqueda del header busca pacientes por nombre o DNI en tiempo real. Al hacer clic en un resultado, abre directamente la ficha del paciente en el módulo de Pacientes.

Módulo Clínico
Pacientes
Expedientes, historias clínicas, evoluciones y seguimiento completo del paciente.

Crear un expediente nuevo

1

Clic en "+ Nuevo Expediente"

En la columna izquierda. El formulario aparece en el panel derecho listo para completar.

2

Ingresá el DNI primero

El sistema verifica automáticamente si ya existe un expediente con ese DNI. Si hay un duplicado, aparece una alerta roja con un botón para ir al expediente existente.

3

Completar datos personales

Nombre, fecha de nacimiento, sexo, teléfono, email, localidad, obra social, contacto de emergencia. El campo de Alergias es crítico — si el paciente tiene alergias, describirlas en detalle.

4

Guardar datos

Clic en "Guardar Datos". El expediente queda creado y aparece en la lista izquierda.

Alerta de alergias

Si un paciente tiene alergias declaradas (que no sean "NINGUNA"), al abrir su ficha aparece un banner rojo pulsante en la parte superior del formulario. Este banner es visible antes de cualquier otra acción para garantizar la seguridad clínica.

Cargar una evolución clínica

1

Abrí la ficha del paciente

Desde la lista o usando el buscador por nombre o DNI.

2

Scrolleá a la sección "Nueva Evolución"

Encontrarás campos específicos: Motivo de consulta, Diagnóstico, Plan / Próxima sesión, Notas, y Mediciones (peso, presión, etc.).

3

Guardar evolución

La evolución queda registrada con fecha, hora y el nombre del profesional que la cargó. Aparece en el historial ordenado del más reciente al más antiguo.

Exportar lista de pacientes

Botón "📊 Exportar lista Excel" debajo de "+ Nuevo Expediente". Descarga un archivo Excel con todos los datos personales (no clínicos) de todos los pacientes, ordenados alfabéticamente.


Incluye: Nombre, DNI, Fecha Nac, Sexo, Tel, Email, Localidad, Obra Social, Contacto Emergencia, Fecha Alta, Alergias.

Descargar Historia Clínica

Botón "📄 Descargar HC" en la ficha del paciente. Genera un PDF con header institucional, datos personales y todas las evoluciones clínicas registradas.

Exportar datos del paciente (ARCO — Ley 25.326)

Botón "🔒 Exportar datos (ARCO)" en la ficha del paciente. Sirve para cuando un paciente ejerce su derecho de acceso a sus datos personales (Ley 25.326 de Protección de Datos). Genera un documento formal titulado "Constancia de Datos Personales" con todos los datos del paciente y una aclaración legal.


⚠ Contiene datos sensibles de salud. El sistema pide confirmar antes de generarlo y registra la exportación en auditoría. Entregalo únicamente al propio paciente o a quien él autorice.

Adjuntar estudios / laboratorios

En la pestaña Archivos de cada paciente. Esta función estará disponible próximamente (requiere activar el almacenamiento en la nube). Cuando se habilite, vas a poder subir informes de laboratorio en PDF (máximo 5 MB). Por ahora, conservá los informes en tu carpeta habitual.

Filtros de la lista

  • Todos: muestra todos los pacientes activos.
  • ⚠ Alergias: filtra solo pacientes con alergias declaradas.
  • Deuda: filtra pacientes con planes de pago pendientes.
Módulo de Gestión
Agenda
Turnos, vistas diaria y semanal, recordatorios por WhatsApp.

Agendar un turno

1

Seleccionar fecha y hora

Elegí el día en el calendario y el horario disponible. Los horarios se configuran en Admin → Agenda y Espacios.

2

Ingresar el paciente

Escribí el nombre o DNI en el campo de paciente. El autocompletar muestra sugerencias de la base de datos. Si el paciente no existe, podés cargarlo desde Pacientes primero.

3

Completar el turno

Elegí el profesional, el tipo de tratamiento, la sala y las observaciones si corresponde.

4

Guardar

El turno aparece en la vista del día y la semana. Podés enviar un recordatorio por WhatsApp desde la tarjeta del turno.

Vista Diaria

Muestra todos los turnos del día seleccionado ordenados por horario. Las tarjetas muestran nombre del paciente, horario, profesional y estado. Las flechas ← → navegan entre días.

Vista Semanal

Toggle DÍA / SEMANA en la toolbar. Muestra 7 días en columnas. El día de hoy aparece resaltado. Las flechas avanzan o retroceden 7 días. Ideal para ver disponibilidad de la semana de un vistazo.

Estados de turno

Programado

Turno confirmado, paciente aún no llegó.

En curso

Paciente presente en la clínica.

Atendido

Turno completado.

Reprogramado

El paciente cambió el horario.

Cancelado

El paciente canceló.

Ausente

No se presentó sin avisar.

PDF de agenda semanal

Botón "📄 PDF Semanal" en la toolbar. Genera un PDF con todos los turnos de la semana visualizada, con el header institucional de Sanalys. Útil para imprimir y tener en recepción.

WhatsApp desde la agenda

Cada tarjeta de turno tiene un botón de WhatsApp que abre una conversación con el paciente con un mensaje de recordatorio pre-cargado. El número se toma automáticamente de la ficha del paciente.

Confirmar tratamiento

El stock se descuenta automáticamente en Laboratorio

Sala de espera

Muestra en tiempo real los pacientes que tienen turno hoy y ya llegaron. Se actualiza automáticamente cada 30 segundos y también cuando alguien registra una llegada. Desde cada tarjeta podés:


  • Ver los datos del paciente y sus alergias
  • Registrar sus vitales del día
  • Iniciar el tratamiento con la fórmula seleccionada
  • Ver el timer de la infusión en curso

Alerta de stock insuficiente

Antes de confirmar una fórmula, el sistema verifica que haya suficiente stock de todos los componentes. Si algún insumo está por debajo de la dosis requerida, aparece un aviso de stock insuficiente antes de ejecutar el descuento.

Importante: vinculación con Caja

El descuento de stock ocurre cuando se confirma el ticket en Caja, no cuando se inicia el tratamiento en Enfermería. Esto garantiza que el stock no se descuente si el cobro no se completa.

Módulo de Stock
Laboratorio
Insumos, fórmulas, pedidos inteligentes e historial de stock.

Pestañas del módulo

Stock de Insumos

Catálogo completo con nombre, concentración, stock disponible, costo y vencimiento. Permite agregar, editar y ajustar el stock manualmente.

Fórmulas

Protocolos de tratamiento compuestos por múltiples insumos con dosis específicas. El costo se calcula automáticamente. Cuando se aplica una fórmula, el stock de cada componente se descuenta.

Pedido Inteligente

Calcula automáticamente qué insumos hay que reponer basándose en el consumo real de los últimos 30 días y el stock disponible actual.

Historial de Pedidos

Registro de todos los pedidos realizados, con fecha, proveedor, cantidades y costos. Útil para proyectar compras futuras.

Cargar un insumo nuevo

1

Completar el formulario de Alta de Insumo

Nombre del principio activo, laboratorio/proveedor, tipo de presentación, concentración, volumen por vial, costo y lote/vencimiento.

2

Indicar stock inicial

Cantidad de viales/unidades que entraron. Este es el stock disponible inicial.

3

Configurar el mínimo

El campo "Mínimo de viales" define cuándo aparece la alerta en el Index. Si lo dejás vacío, usa el mínimo global configurado en Admin.

Crear una fórmula / protocolo

En la pestaña Fórmulas, ingresá el nombre del protocolo y agregá los insumos uno por uno con sus dosis. El sistema calcula el costo total automáticamente y verifica si hay stock suficiente para prepararla.


⚠ Si un componente tiene stock insuficiente, la fórmula aparece con una advertencia en rojo antes de confirmarla.

Módulo Legal
Consentimientos
Consentimientos informados digitales con firma en pantalla.

Activación del módulo

El módulo de consentimientos debe estar habilitado en Admin → Config del Sistema → activar "Consentimientos Digitales". Si el panel aparece deshabilitado, es porque esta opción está apagada.

Crear un consentimiento

1

Buscar al paciente

Ingresá el nombre o DNI. El sistema autocompleta los datos del paciente desde la base de expedientes, incluyendo las alergias declaradas.

2

Seleccionar el tipo de consentimiento

Los tipos disponibles se configuran en Admin. Al seleccionar uno, se carga automáticamente el texto predefinido, que podés editar antes de guardar.

3

Checklist obligatorio

El paciente debe confirmar que: se le explicaron los riesgos, conoce las alternativas, sus preguntas fueron respondidas, acepta voluntariamente y puede retirarse cuando quiera.

4

Firma digital

El paciente firma en el canvas usando el dedo (tablet/celular) o el mouse. Clic en "Limpiar" para volver a firmar si es necesario.

5

Guardar y PDF

Al guardar, se genera automáticamente el PDF con header institucional, texto completo, checklist firmado y la firma digital del paciente.

Enviar por WhatsApp

Después de guardar aparece el botón "💬 Enviar por WhatsApp". Abre una conversación con el paciente con un mensaje de confirmación pre-cargado. El número se toma de su ficha.

Historial de consentimientos

La columna izquierda muestra todos los consentimientos emitidos, ordenados del más reciente al más antiguo, con indicador de si están firmados o pendientes. Clic en uno para regenerar el PDF.

Configurar textos predefinidos

Los textos que se cargan automáticamente al seleccionar un tipo de tratamiento se editan en Admin → Config del Sistema → Textos Consentimientos. Si un texto queda vacío, el área de texto aparece en blanco para escribir en el momento.

Módulo Financiero
Caja
Ingresos, egresos, traspasos, tickets de cobro y cierre de turno.

Tipos de movimiento

OI — Ingreso

Cobros por tratamientos, consultas y servicios. Siempre requiere DNI del paciente para vincular con la historia clínica.

OE — Egreso

Gastos operativos: insumos, servicios, sueldos, alquiler, etc.

OT — Traspaso

Movimiento de fondos entre cuentas internas. No afecta la utilidad.

OR — Retiro

Distribución de utilidades entre las socias.

CC — Centro de Costo

Movimiento asignado a un centro de costo específico.

Armar un ticket de cobro (flujo recomendado)

1

Ingresar el DNI del paciente

El sistema verifica que exista en la base. El DNI vincula el cobro con la historia clínica del paciente.

2

Seleccionar el tratamiento o suero

Si el paciente recibió un suero IV, seleccioná la fórmula aplicada. El precio se completa automáticamente. Podés agregar múltiples ítems al mismo ticket.

3

Seleccionar medio de pago

Efectivo, banco, billetera virtual u otro. El saldo se acredita en la cuenta correspondiente.

4

Confirmar cobro

El movimiento queda registrado con número correlativo (OI-26-XXXX), fecha, monto y profesional. Si la fórmula tenía sueros, el stock se descuenta automáticamente.

Alerta de monto inusual

Si cargás un monto mayor al máximo configurado (definido en Admin → Configuración de honorarios), el sistema te pide confirmar antes de guardar: "El monto es $X, es más alto que el máximo. ¿Es correcto?". Sirve para atrapar errores de tipeo (un cero de más, el punto mal puesto). No bloquea: podés confirmar si el monto es correcto. El máximo lo ajusta la administradora según la inflación.

Numeración correlativa

Cada movimiento recibe un número único con formato TIPO-AÑO-NÚMERO. Ejemplo: OI-26-0001. La numeración reinicia cada año y es independiente por tipo de movimiento. Nunca se repite.

Anular un movimiento

Los movimientos no se borran. Para corregir un error, se anula el movimiento y se crea uno nuevo correcto. Al anular, el sistema pide obligatoriamente un motivo de anulación que queda registrado en auditoría.

Cierre de turno

Al final de cada turno, el botón "🔒 Cierre de Turno" abre el panel de arqueo. Ingresás los billetes físicos contados (o el total directamente) y el sistema compara contra el saldo calculado del software.


⚠ Si hay una diferencia (falta o sobra plata), el sistema te pide obligatoriamente un motivo antes de cerrar. Esto te obliga a controlar por qué hay diferencia, o a cancelar y revisar antes de cerrar. El motivo queda guardado en el arqueo y aparece en el PDF, para control de las socias.

Consultar arqueos anteriores

El botón "🔎 Consultar Arqueos" abre un buscador de cierres de turno pasados, filtrable por fecha y por cajero. De cada arqueo podés descargar su PDF, que incluye los billetes contados, la diferencia y el motivo (si lo hubo). Ideal para que las socias revisen los cierres.

PDF Reporte

Genera un PDF del día actual con todos los movimientos, totales por cuenta y balance. Útil para entregar al final del turno.

Exportar Excel

Botón "📊 Exportar Excel". Descarga todos los movimientos no anulados con todos los campos en un archivo .xlsx. Ideal para contabilidad externa.

Módulo Financiero
Balance
P&L, EBITDA, inversiones, deudas y libros contables.

Panel de indicadores

Ingresos totales

Suma de todos los cobros del período seleccionado.

Egresos totales

Suma de todos los gastos fijos y variables.

EBITDA

Resultado neto antes de impuestos y amortizaciones.

Saldos por cuenta

Muestra el saldo actual de cada cuenta (Efectivo, Bancos, Billeteras, Tránsito) calculado desde todos los movimientos de Caja. El saldo "en tránsito" corresponde a pagos entre socias que aún no se distribuyeron.

Libros contables

Botón "📊 Libro Diario / Balance". Genera el Balance de Sumas y Saldos y el Libro Diario con filtros por fecha y cuenta contable. Los egresos aparecen destacados en rojo para facilitar la lectura contable.

Inversiones

Registro de FCI, plazos fijos, criptomonedas y otros activos de la sociedad. Muestra capital invertido, valor actual y rendimiento porcentual en tiempo real.

Deudas

Registro de obligaciones pendientes (proveedores, préstamos, etc.) con monto, vencimiento y estado. El total de deudas aparece en el dashboard de Balance.

Módulo de Gestión
CRM
Pipeline de leads, seguimiento, bitácora y conversión a paciente.

Pipeline de etapas

Nuevas Consultas

Leads que acaban de entrar en contacto. Primera etapa del funnel.

En Seguimiento

Leads con los que ya hubo contacto y están evaluando.

Presupuesto Enviado

Leads que recibieron información y precio.

Convertidos

Leads que se convirtieron en pacientes. Fin del pipeline.

Cargar un lead nuevo

1

Botón "+ Nuevo Lead" o "+ Nueva Consulta"

Abre el formulario de carga rápida con nombre, teléfono, origen e interés.

2

Completar los datos

Origen (Instagram, WhatsApp, Recomendación, Web) e interés (Sueros IV, Medicina Ortho, etc.) ayudan a segmentar y priorizar.

3

Asignar próximo contacto

La fecha de próximo contacto aparece en el Index cuando llega el día, para no perder de vista ningún seguimiento.

Bitácora de seguimiento

En el panel lateral de cada lead podés agregar notas de seguimiento clasificadas como:


  • Próximos Pasos: acción definida a tomar
  • Positivo: señal de avance (interés confirmado, precio acordado)
  • Neutro: actualización sin evaluación

Convertir en paciente

Cuando un lead confirma que quiere empezar, hacé clic en "✓ Convertir en Paciente" al fondo del panel lateral. El sistema:


  • Crea el expediente en Pacientes con nombre y teléfono pre-cargados
  • Marca el lead como "Convertido" en el CRM
  • Redirige a Pacientes con el expediente ya abierto
  • Te pide que completes DNI, fecha de nacimiento y alergias

⚠ Si el lead ya fue convertido antes, el sistema avisa y no crea un duplicado.

Módulo de Configuración
Admin
El cerebro del sistema. Configura todo lo que usan los demás módulos.

Acceso restringido

Solo los usuarios con permiso admin pueden acceder a este módulo. Los cambios en Admin afectan a toda la clínica en tiempo real.

Pestañas del módulo

Personas y Roles

Alta y edición de médicas, socias y otros profesionales. Configurá nombre, especialidad, matrícula, porcentaje de honorarios y participación en sociedad. Esta lista alimenta los selectores de "Profesional" en Caja y Agenda.

Honorarios y Reparto

Consulta de honorarios por día y por mes por profesional. Genera el PDF de liquidación mensual con desglose por profesional y totales. También configura el porcentaje de retiro de cada socia.

Plan de Cuentas

Define las categorías de ingresos, egresos fijos, egresos variables y centros de costo. Estas categorías son las que aparecen en los selectores de Caja y Balance. Cambios en tiempo real.


Botón "📄 Descargar PDF" genera un documento de Plan de Cuentas contable listo para imprimir.

Agenda y Espacios

Configura los horarios de atención (mañana y tarde), duración de los turnos, días habilitados y las salas/espacios físicos disponibles.

Usuarios y Accesos

Alta, edición y desactivación de usuarios del sistema. Para cada usuario configurás:


  • Nombre y email (el email debe existir en Firebase Authentication)
  • Permisos por módulo: Pacientes, Inventario, Fórmulas, Tesorería, Balance, Agenda, Enfermería, Sueros/Lab, Legal, Administración total

⚠ Los botones "Desactivar" y "Activar" son reversibles. "Eliminar" es permanente y requiere confirmación.

Config del Sistema

Configuraciones globales que afectan a todos los módulos:


  • Datos de la Clínica: nombre, dirección, teléfono, email, redes sociales y slogan. Estos datos aparecen en el footer de todos los PDFs.
  • Alertas: días de inactividad para alerta naranja en Index, y stock mínimo global para alerta roja.
  • Medios de Pago: lista de cuentas disponibles en Caja.
  • Tipos de Tratamiento: lista dinámica que alimenta el selector de Consentimientos.
  • Textos Consentimientos: texto predefinido para cada tipo de tratamiento.
  • Funcionalidades: activa o desactiva módulos como Consentimientos Digitales.

Auditoría y Respaldo

Registro completo de todas las acciones del sistema (quién hizo qué y cuándo). Backup descargable en formato JSON desde Admin → Backups.


⚠ La auditoría es permanente: no se puede borrar ni modificar.

Gestión de datos

Por seguridad, el sistema ya NO incluye funciones de borrado masivo ni "formateo" (se eliminaron porque eran un riesgo). Para borrar o restaurar datos de forma controlada, seguí las instrucciones detalladas en Admin → Backups → "Gestión de datos en producción", que te guían paso a paso desde Firebase Console.


Lo que se conserva siempre: usuarios, personas, configuración del sistema, plan de cuentas y auditoría.

Referencia
Seguridad
Capas de protección del sistema y buenas prácticas.

Capa 1 — Firebase Authentication

El primer control es Firebase Auth. Sin una cuenta creada en Firebase, no se puede entrar al sistema aunque se tenga el email en Firestore. Las cuentas las crea el administrador desde la consola de Firebase.

Capa 2 — Documento de usuario activo

Después del login, el sistema verifica que exista un documento en la colección usuarios con activo: true. Un usuario desactivado desde Admin no puede entrar aunque tenga cuenta en Firebase.

Capa 3 — Permisos por módulo

Cada módulo verifica al cargar si el usuario tiene el permiso correspondiente. Si no lo tiene, redirige al Index. Los usuarios con permiso admin saltan esta verificación y acceden a todo.

Capa 4 — Inactividad automática

La sesión se cierra automáticamente después de 30 minutos sin actividad. Esto protege las estaciones de trabajo que quedan desbloqueadas sin supervisión.

Capa 5 — Cierre de sesión real

Al cerrar sesión (manual o por inactividad), el sistema desconecta la sesión real de Firebase, no solo la pantalla. Esto evita que quede una sesión activa por detrás. El tiempo de inactividad antes del cierre automático lo configura la administradora desde Admin → Alertas y Sesión.

Auditoría permanente

Todo queda registrado en la colección auditoria de Firestore: qué se hizo, quién lo hizo, cuándo. Esta colección tiene una regla de Firestore que impide el borrado incluso desde la consola de Firebase. Es la caja negra del sistema.

Buenas prácticas

  • Nunca compartir contraseñas entre usuarios. Cada persona tiene su propio acceso.
  • Cerrar sesión al alejarse de la computadora.
  • Usar contraseñas de al menos 8 caracteres con letras y números.
  • Hacer backup mensual desde Admin → Backups.
  • Si un empleado deja la clínica, desactivar su usuario inmediatamente desde Admin → Usuarios.
  • Dar a cada usuario solo los permisos de los módulos que realmente necesita para su trabajo.
Referencia Técnica
Configuración Firebase
Alta de usuarios, Storage para archivos, reglas de seguridad y administración de la base de datos.

Crear un usuario nuevo en Firebase Auth

Hasta que esté disponible la Cloud Function de alta automática, los usuarios se crean manualmente en la consola de Firebase y después se registran en Admin.


1

Ir a console.firebase.google.com

Seleccionar el proyecto sanalys-2263e.

2

Authentication → Usuarios → Agregar usuario

Ingresar el email y una contraseña temporal. El usuario recibirá el acceso con esas credenciales.

3

Registrar el usuario en Sanalys Admin

Entrar al sistema → Admin → Usuarios y Accesos → completar nombre, email (mismo que en Firebase) y asignar los permisos correspondientes → Guardar.

4

El usuario entra por primera vez

Cuando el usuario inicia sesión por primera vez, el sistema guarda automáticamente su UID de Firebase en Firestore. Desde ahí queda completamente operativo.

5

El usuario cambia su contraseña

Desde la pantalla de login → "¿Olvidaste tu contraseña?" → recibe el email de Firebase → setea su propia clave segura.

Agregar campo activo a usuarios existentes

Si un usuario ya existía en Firestore antes de que se implementara el campo activo, hay que agregarlo manualmente una sola vez:


1

Firestore → colección usuarios

Abrir el documento del usuario (identificado por su email).

2

+ Agregar campo

Campo: activo — Tipo: boolean — Valor: true → Actualizar.

3

Repetir para cada usuario

Hacerlo en todos los documentos de la colección usuarios.

Activar Firebase Storage (archivos y fotos)

Para habilitar el guardado de PDFs, fotos de estudios y archivos adjuntos en las fichas de pacientes, hay que activar Firebase Storage. Requiere el plan Blaze (pago por uso — el costo es mínimo para el volumen de una clínica).


1

Actualizar al plan Blaze

En la consola de Firebase → menú inferior izquierdo → "Spark" → "Actualizar" → seleccionar Blaze → configurar facturación. El primer GB de storage es gratis.

2

Activar Storage

En el menú izquierdo → Storage → "Comenzar" → elegir la región us-central1 (más cercana con menor latencia para Argentina).

3

Configurar las reglas de Storage

En Storage → pestaña Rules → reemplazar el contenido por:

rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /{allPaths=**} {
      allow read, write: if request.auth != null;
    }
  }
}

Clic en Publicar. Esto permite que cualquier usuario autenticado pueda subir y leer archivos.

Reglas de Firestore actuales

Las reglas actuales del sistema están en modo permisivo — cualquier usuario autenticado puede leer y escribir. Esto es funcional pero no es la configuración más segura.


rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if true;
    }
  }
}

⚠ La mejora de seguridad con Custom Claims está en el roadmap. Se implementará junto con la Cloud Function de alta de usuarios.

Backup de Firestore

Además del backup integrado en Admin, podés hacer un backup completo manual desde Firebase:


1

Firestore → menú de tres puntos → Exportar datos

Exporta todas las colecciones a un bucket de Google Cloud Storage. Requiere plan Blaze.

2

Backup desde Admin (recomendado)

Admin → Auditoría y Respaldo → Backup completo. Descarga un JSON con todos los datos operativos. Guardarlo en un lugar seguro fuera del sistema.

Referencia Técnica
Despliegue
Cómo actualizar el sistema en producción via Netlify.

Subir una actualización

1

Obtener el ZIP actualizado

El desarrollador entrega el archivo sanalys-v2.zip con los archivos actualizados.

2

Entrar a Netlify

Ir a app.netlify.com con la cuenta de Sanalys. Seleccionar el proyecto.

3

Pestaña "Deploys"

Arrastrar la carpeta sanalys-v2 (no el ZIP) al recuadro gris que dice "Drag and drop your site folder here". El deploy tarda 30-60 segundos.

4

Verificar el deploy

Cuando aparece el indicador verde "Published", el sistema está actualizado. Refrescar el browser con Ctrl+Shift+R para limpiar caché.

Testing local

Para probar cambios antes de subir a producción:


1

Abrir VS Code

Abrir la carpeta completa sanalys-v2.

2

Live Server

Clic derecho en index.html → "Open with Live Server". Se abre en http://127.0.0.1:5500.

3

Importante

⚠ Nunca abrir los archivos con doble clic (protocolo file://). Firebase y ES6 modules requieren un servidor HTTP como Live Server.

Stack tecnológico

Firebase

Autenticación (Auth) + Base de datos (Firestore). Serverless, sincronización en tiempo real.

Netlify

Hosting estático. Deploy vía drag & drop. CDN global.

Tailwind CSS

Framework de estilos via CDN. Sin compilación.

jsPDF + autoTable

Generación de PDFs en el browser. Sin servidor.
